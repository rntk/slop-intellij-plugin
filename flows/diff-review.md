# Diff review flow

Diff Review is a standalone, read-only workspace for reviewing code changes with AI assistance, independent of the application graph. It lives in `src/main/kotlin/dev/insight/diff`.

At a high level: the workspace loads an immutable snapshot of a selected comparison (such as local uncommitted changes or a Git revision comparison) and presents the changed files for reading. Each review tab is an independent session over that snapshot, optionally scoped to a subset of files. Within a tab, the user chats with an assistant that can only inspect the snapshot; it can place explanatory notes, source excerpts, diagrams, and file diffs alongside the changed files for closer reading.

The assistant can also point to specific snapshot lines in native, read-only editors, with an optional comment. Each point opens its own side-by-side column. Chat tools follow the review context; dedicated generation commands expose their own tools only when needed.

The chat's **Files** tab reports requested files and the snapshot content supplied to the model, with coverage, line ranges and exact excerpts by turn and request. Diff coverage is separate from the source exposed on each comparison side: reading every change does not imply reading the whole file. Requests that fail or are cancelled do not count as accepted evidence, and context eviction remains visible when inspecting individual requests.

Generated views help navigate a large change — for example summaries of what changed, topics grouping files by responsibility, and flows showing how changed code connects. Code builds the underlying structure from the snapshot; the assistant only writes or labels the interpretation. Words scatters the words of the changed lines from removed to added, sized by frequency. A separate Diff overview fills opposite corners with compact deleted and added word lists around a small chart comparing deleted and added line counts. Both are counted by code alone; a word opens the diffs of its files. Both views can be scoped to one changed file or directory, picked from a list filtered by typing. Metrics counts the parsed source of both sides of every changed file by code alone and shows it as a table of totals before and after, a scatter of each function's complexity before against after, or a cloud of the constructs added and removed; a row, point or construct opens the diffs it comes from. Everything in a review is tied to its snapshot, so it is refreshed or discarded when the comparison changes.

In Summaries, files can also be opened as complete, read-only snapshot source (the previous version for deleted files). Folder actions open all changed files beneath that folder in one navigable diff viewer, within the review tab's scope.

The Summaries outline always shows file and folder names, with metadata and file actions on the same header line. Clicking a summary expands or collapses its children, like its arrow; scored words retain their context and search actions. Selecting text in a summary and choosing Search from its context menu runs the same search for the selection, without needing Score first. A left click on a scored word does not search, so it can place the caret or start a selection; right-clicking a scored word and choosing Search from its context menu runs the word's search. File and part summaries are scored too: choosing Search on a highlighted word in one scores the blocks of the file's changed lines against the word's query, then the lines of the best block, and opens the diff scrolled to those lines with them highlighted. Outline and Hierarchy show scoring and hover status in a fixed footer so hints do not move the summaries.

In Topics, both Document and Hierarchy have two separate fuzzy filters: one matches each file’s topic, the other its name, path and summary. Files must match both; topics left without files hide, and the summary filter opens the topics above its matches.

Entry points for further exploration:

- [DiffReviewPanel.kt](../src/main/kotlin/dev/insight/diff/DiffReviewPanel.kt) — tool window entry point: comparison and file selection, review tabs
- [DiffReviewTab.kt](../src/main/kotlin/dev/insight/diff/DiffReviewTab.kt) — per-tab session: chat, workspace, and generated views

From there, neighbouring files in the same package cover snapshot loading, assistant tools, and the individual generated views. Diff Review also shares workspace and summary machinery with [Code Review](code-review.md).

Summaries, topics, topic hierarchy texts (Fill summaries), and word scores persist across IDE restarts in the project’s `.insight/review-cache/` directory, one slot per comparison request and tab scope. Saved entries are keyed by their evidence rather than by the whole snapshot: a summary by its node key, which covers every file and part beneath the node, a topic by its file’s path and fingerprint, and a word score by its full judgment request (model, rules, summary texts and question). A changed file therefore regenerates only its own summary, topic and scores and those of the folders, groups, topics and root above it; everything else is restored. File fingerprints use project-relative paths and content, or, for unreadable files, revisions and the on-disk time and length, so they survive a restart. A slot keeps entries of earlier snapshots too, oldest dropped first, so reverting an edit restores its results. Partial runs are saved incrementally. Regenerate drops the saved entries of that kind for every snapshot of the slot. Chat, notes, source cards, and flows are not persisted. The cache contains its own Git ignore file; delete it while the IDE is closed to clear saved results.
