# Charts tab flow

The Charts tab is a shared way to explore the file and directory structure of a review through visual summaries. In Code Review, it describes the selected code scope; in Diff Review, it describes the selected comparison. Readers move between a hierarchical line view, whose folders unfold in place and whose rows can be followed with the mouse or keyboard, a pannable/zoomable tree board view that lays out the whole project structure as a foldable ASCII-style diagram with active and hovered branch highlighting, a circles view that packs the same directory into nested circles sized by the current metric and walks into a folder on click, and a radar view, then can open relevant summaries or source/diff context from the chart. The tab is presented by shared review UI and receives review-specific data from its caller.

The hierarchy has metric tabs for source lines, captured source size in bytes, and file counts in Code Review. Diff Review uses green Added lines and red Removed lines tabs. The hierarchy, the tree board, and the circles share these tabs, the search and the current directory. Changing the metric keeps the current directory, collapsed folders, cursor, and open preview. Circles and radar icons on each file and directory open the corresponding chart to the right of the hierarchy using the current metric.

In the Tree chart, each file has a code connections control. It draws incoming and outgoing links between file rows on the right, using imports and references resolved from the IDE's current source. Hovering near a link highlights its full route, shows the source and target paths, and opens a small preview window showing short, visually separated side-by-side source snippets from both files for all resolved occurrences (calls, usages, inheritance, and imports) between them. Clicking a link pins that preview window so you can scroll through all occurrences or jump to a line in either file; clicking "Open context…" in the preview or right-clicking the link opens the [context picker](context-picker.md) for both files and opens them together in a [canvas session](canvas-session.md). The canvas scrolls the source card to the call or reference and the target card to the resolved declaration when available. If several sites connect the same files, the primary navigation site uses the first call, then a usage, then an import. The links are scoped to files in the review. Folders, metric tabs, and search still determine which rows are visible.

Each file and directory in the Tree chart also has a focus control (or press `F`). Activating it reduces the tree to a compact subtree containing only the focused file (or the focused directory's files), all directly linked incoming and outgoing files, and their ancestor directories—hiding unrelated files and folders while preserving the tree structure. Focus mode composes with code connections and metric tabs, and can be exited by clicking the focus icon again, pressing `F` or `Esc`, or clicking **Show all** in the toolbar.

In either review, click a Tree link to pin its preview, then choose **Explain connection**. The model receives the source and target locations and their snippets. It can read and search current project files for more context. The explanation appears in a resizable pane below the snippets, with clickable file, line, and symbol references as in the [report viewer](report-viewer.md). Reopening the pinned preview shows the completed explanation immediately. It stays in memory until the connection index is rebuilt. Closing the preview cancels a pending explanation.

Each Tree file also has a summarize control (or press `S`). It shows the file's links and has the model write one-line briefs next to the rows: what the file does, and how each linked file uses it or is used by it. Each brief stays on one line so the tree layout doesn't change, and links are drawn to the right of the briefs. Briefs appear as they finish, with clickable file, line, and symbol references like those in the [report viewer](report-viewer.md). Like explanations, they stay in memory until the connection index is rebuilt. Showing another file's links or toggling the control again hides them.

When generated [summaries](summaries.md) exist for files in the review (such as diff summaries in Diff Review), each summarized Tree file shows a summary icon (or press `D`) to toggle its summary inline beneath its row, and the Tree control panel includes a **Show summaries** / **Hide summaries** button to show or hide all available file summaries at once. The inline summaries parse and link file paths, line references, and code symbols the same way the [report viewer](report-viewer.md) does.

A one-line search above the hierarchy asks the model which files match a short query. The model explores with the review's own read-only tools and answers only with paths. The answer becomes a Search tab, not a filter on the current tab. That tab shows the usual hierarchy and drill-down with every unrelated file and folder hidden; returned paths are matched leniently against the review's files and folders.

In Code Review, the tabs also act as semantic lenses over the code: classes, functions, constants, tests, imports and other kinds recognized syntactically through PSI by each supported language. A lens counts only its kind and hides entries without it; only the kinds present in the scope get a tab. Parsed files unfold into declarations and members. Readers can preview their source, open them in the editor, or request a summary of a single declaration. The row's [context picker](context-picker.md) opens on the declaration's source range. The chart and [Canvas sessions](canvas-session.md) reuse declaration summaries for matching source. File and directory summaries keep their own review workflow.
